A Claude-style agent that makes videos

In-app agent architecture for agent-media · 2026-05-31

TL;DR. Don't build a new generator. Build a thin orchestration brain on top of the skills you already ship. Every capability is already a self-describing, agent-callable tool (/v1/skills + social endpoints), auth & credits are wired, and you just proved the full chain by hand. The agent's only new job is: pick the next skill, run it, wait durably, continue. The single hard problem is that renders take minutes — so the agent must be event-driven and resumable, not a blocking chatbot.

Green-field code is only the brain + executor + session store + chat panel. Skills, credits, R2, gallery, social — all reused.

1 · The brain (Claude tool-use loop)

A standard Anthropic tool-use loop. Tools are generated from the skill registry — /v1/skills already returns each skill's JSON input schema, so the toolset is never hand-maintained. System prompt = the existing agent-media-ugc playbook (patterns A/B/C, pacing, realism, "reuse a character_sheet_url").

Plan-then-act: for any multi-step / spend-incurring request the brain first emits a short plan + credit estimate and calls request_confirmation; it only proceeds on a yes. This is the cost guardrail and the trust moment.

2 · The crux — long-running tools

Renders take 1–7 min. A chat loop can't block on that. So generation tools are deferred:

  • A generation tool_use submits the skill run and returns immediately: { run_id, status:"submitted" }. The turn ends — the brain tells the user "generating ~5 min".
  • The durable executor watches the run (Temporal completion signal, or poll). When it finishes, it appends the real tool_result (the video_url / artifacts) to the transcript and re-invokes the brain for one more turn — which either fires the next step or finalizes.
  • Repeat until the brain stops calling generation tools. The agent is a resumable state machine, not one long request.

This is why it survives a tab close: the transcript + live runs are persisted; reconnecting just replays them and streams the rest.

3 · Durability — two options

A · App-loop + queue simplest v1

Brain runs in an api-v2 route. Deferred runs tracked in agent_messages. A lightweight worker (or Temporal poll / Vercel Queue) detects completion and triggers the next brain turn. Fastest to ship; good enough for single linear chains.

B · Agent-as-Temporal-workflow most robust

Model the whole session as a Temporal workflow: an askClaude activity between steps, child skill workflows for renders, signals to resume. You already run Temporal for the skills — this gives crash-proof, multi-step, multi-minute agents for free. Recommended once v1 proves the UX.

5 · Web UI

  • Chat panel at /dashboard (or a slide-over). Streams tokens + tool-call cards ("running make_product_in_hands…") and renders intermediate media inline as each step lands.
  • Built on the Vercel AI SDK (streaming + tool-call UI for free) — but generation tools resolve via the deferred pattern above, not blocking.
  • Human-in-loop inline: confirm-spend buttons; "Connect TikTok" opens the OAuth URL; "Publish" is an explicit click.

6 · Guardrails

  • Credits: per-turn + per-session cap; plan+estimate+confirm before any chain. The agent can never loop-spend.
  • Outward actions (publish, OAuth) always require an explicit user confirm — never auto-posted.
  • Acts as the user (their token) → existing credit ledger, gallery, RLS all apply unchanged.
  • Full transcript persisted = auditability + resume.

Phased build

v1 Chat panel + brain (app-loop) + deferred generation tools, creation-only. Ship the "type it, watch it build" moment. ≈ the chain you already ran, automated

v2 Add publish + connect (human-in-loop), character reuse, plan/confirm + credit caps.

v3 Move the session onto Temporal (option B) for crash-proof long agents; multi-channel publish; scheduling.

The whole bet: the skill platform you sell to outside agents is the engine for your own in-app agent. You're not building a second system — you're pointing Claude at the one you have.
