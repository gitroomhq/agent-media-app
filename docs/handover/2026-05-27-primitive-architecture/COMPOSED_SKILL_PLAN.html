What's missing for the "describe OR upload → finished video" UX

To get a video out the door today a user needs three separate API calls:

  1. POST /v1/skills/make_portrait/run → wait → get portrait_url
  2. POST /v1/skills/make_character_sheet/run → wait → get sheet_url
  3. POST /v1/skills/make_simple_selfie/run → wait → get video_url

That's not a product UX. We need a composed skill that does all three in one call.

What we'd build: make_ugc_video (composed skill)

Input (one call)

POST /v1/skills/make_ugc_video/run
{
  // EXACTLY ONE source of identity:
  "description":  "a friendly young woman, soft daylight",          // text-only OR
  "portrait_url": "https://pub-...r2.dev/...",                       // OR R2 url OR
  "portrait_image_base64": "iVBORw0KGgo...",                         // OR uploaded bytes

  // What they say:
  "script":   "Honestly, this app changed my morning routine.",      // word count 2-4 wps
  "duration": 5,                                                     // 5 | 10 | 15

  // Optional:
  "character_description": "Sara, 28 years old",                     // ≤10 words for sheet
  "location": "bright kitchen window light",
  "pose":     "leaning slightly on counter"
}

What happens server-side (one Temporal workflow, three steps)

StepActivityNote
0normalize inputIf base64 → R2 upload. If description only → step 1. If portrait_url → skip to step 2.
1portraitGpt2only when no portrait was supplied

Status surface (one run_id, the user polls)

GET /v1/skills/runs/{skill_run_id}
→ {

      { "primitive": "simple_selfie",         "status": "pending",   "url": null }

Things NOT in this composed skill

  • Wireframe step — the prod selfie pipeline has it for scene continuity. Simple UGC video can skip it; we'll add a make_ugc_video_pro later if needed.
  • Subtitles burn-in — separate subtitles primitive, future composed skill.
  • Product hold — a different composed skill (make_product_ugc_video) when we have the product-handling primitive.

Bottom line

What you need to give a real end-user a "describe OR upload → finished video" flow:

  1. One composed skill (make_ugc_video) — single POST, one workflow, three primitives chained.
  2. One new table pair (skill_runs + skill_run_steps) + a small migration.
  3. One status endpoint (GET /v1/skills/runs/:id).

Time to build: ~1 hour. Cost per call: ~$1.
