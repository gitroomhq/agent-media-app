vNext Primitive Migration — What & Why

File: supabase/migrations/20260527150000_vnext_primitive_runs.sql

What kind of migration is this?

Forward-only, additive Postgres DDL migration. Standard Supabase migration. It only creates new tables, indexes, triggers, and a helper function — it does not alter, drop, or rename anything that already exists. Safe to run on any database that doesn't already have these tables; idempotent thanks to IF NOT EXISTS on every CREATE.

"Additive" means…

  • Existing tables (generation_jobs, user_characters, auth.users, etc.) are untouched.
  • No data is moved, copied, or rewritten.
  • Rolling back = drop the 4 new tables + the trigger function. Nothing else to undo.
  • It is the kind of migration you can apply during a regular deploy with zero downtime — no locks on hot tables.

How it gets applied

  • Local dev: supabase db reset (needs Docker / OrbStack running). Replays every migration in supabase/migrations/ in timestamp order against the local Postgres at localhost:54322.
  • Staging / Prod: applied via your normal Supabase deploy flow (supabase db push or whatever your CI runs). Per the operating rules, this needs Yuval's explicit approval — not run by me.

What it creates

ObjectPurpose
primitive_runs One row per primitive invocation. The vNext equivalent of the old generation_jobs table — but deliberately separate so we don't reuse the legacy ledger. Holds: user_id, primitive_id (e.g. portrait_gpt2), status, input JSON, idempotency key, credit estimates & actuals, error code/message, timestamps.
primitive_artifacts One row per file produced (PNG, MP4, SRT…). Points at R2 via url, has kind + MIME + size + metadata. A run can have many artifacts.
primitive_events Time-ordered event log per run (info / warn / error). Useful for diagnostics + later SSE stream.
provider_tasks External provider task ledger (OpenAI request ids, Seedance task ids, etc.) joined back to primitive_runs. Lets us audit cost/usage per provider.
touch_primitive_updated_at() trigger Auto-updates updated_at on UPDATE. Cosmetic but useful.
Indexes (user_id, created_at DESC) for listing, (primitive_id, status) for ops dashboards, (skill_run_id) WHERE NOT NULL for skill-run grouping, partial unique on (user_id, primitive_id, idempotency_key) for idempotency.
RLS ENABLE ROW LEVEL SECURITY on every table but no per-user policies yet. That means: only the service_role key (worker + api-v2) can read/write today. User-facing reads will land in a follow-up once GET endpoints exist.

The full SQL

Copy of the file content (also at supabase/migrations/20260527150000_vnext_primitive_runs.sql):

-- vNext primitive runtime tables.
--
-- Fresh data plane for the primitive architecture (see
-- docs/handover/2026-05-27-primitive-architecture/). The legacy
-- generation_jobs table is deliberately NOT reused — that was the
-- biggest trap called out by the previous engineer.

CREATE TABLE IF NOT EXISTS public.primitive_runs (
  id uuid PRIMARY KEY,
  user_id uuid NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  skill_run_id uuid,
  primitive_id text NOT NULL,
  status text NOT NULL CHECK (status IN ('submitted', 'running', 'succeeded', 'failed', 'canceled')),
  input jsonb NOT NULL,
  idempotency_key text,
  provider_task_id text,
  estimated_credits_usd numeric(10, 4),
  actual_credits_usd numeric(10, 4),
  error_code text,
  error_message text,
  started_at timestamptz,
  finished_at timestamptz,
  created_at timestamptz NOT NULL DEFAULT now(),
  updated_at timestamptz NOT NULL DEFAULT now()
);

CREATE INDEX IF NOT EXISTS idx_primitive_runs_user_created
  ON public.primitive_runs (user_id, created_at DESC);

CREATE INDEX IF NOT EXISTS idx_primitive_runs_primitive_status
  ON public.primitive_runs (primitive_id, status);

CREATE INDEX IF NOT EXISTS idx_primitive_runs_skill_run
  ON public.primitive_runs (skill_run_id)
  WHERE skill_run_id IS NOT NULL;

CREATE UNIQUE INDEX IF NOT EXISTS uniq_primitive_runs_idempotency
  ON public.primitive_runs (user_id, primitive_id, idempotency_key)
  WHERE idempotency_key IS NOT NULL;

ALTER TABLE public.primitive_runs ENABLE ROW LEVEL SECURITY;

CREATE TABLE IF NOT EXISTS public.primitive_artifacts (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  primitive_run_id uuid NOT NULL REFERENCES public.primitive_runs(id) ON DELETE CASCADE,
  kind text NOT NULL,
  url text NOT NULL,
  bytes bigint,
  mime text,
  metadata jsonb NOT NULL DEFAULT '{}'::jsonb,
  created_at timestamptz NOT NULL DEFAULT now()
);

CREATE INDEX IF NOT EXISTS idx_primitive_artifacts_run
  ON public.primitive_artifacts (primitive_run_id);

ALTER TABLE public.primitive_artifacts ENABLE ROW LEVEL SECURITY;

CREATE TABLE IF NOT EXISTS public.primitive_events (
  id bigserial PRIMARY KEY,
  primitive_run_id uuid NOT NULL REFERENCES public.primitive_runs(id) ON DELETE CASCADE,
  ts timestamptz NOT NULL DEFAULT now(),
  level text NOT NULL CHECK (level IN ('debug', 'info', 'warn', 'error')),
  code text NOT NULL,
  message jsonb NOT NULL DEFAULT '{}'::jsonb
);

CREATE INDEX IF NOT EXISTS idx_primitive_events_run_ts
  ON public.primitive_events (primitive_run_id, ts);

ALTER TABLE public.primitive_events ENABLE ROW LEVEL SECURITY;

CREATE TABLE IF NOT EXISTS public.provider_tasks (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  primitive_run_id uuid NOT NULL REFERENCES public.primitive_runs(id) ON DELETE CASCADE,
  provider text NOT NULL,
  external_task_id text,
  status text,
  raw_response jsonb,
  created_at timestamptz NOT NULL DEFAULT now(),
  updated_at timestamptz NOT NULL DEFAULT now()
);

CREATE INDEX IF NOT EXISTS idx_provider_tasks_run
  ON public.provider_tasks (primitive_run_id);

CREATE INDEX IF NOT EXISTS idx_provider_tasks_external
  ON public.provider_tasks (provider, external_task_id)
  WHERE external_task_id IS NOT NULL;

ALTER TABLE public.provider_tasks ENABLE ROW LEVEL SECURITY;

CREATE OR REPLACE FUNCTION public.touch_primitive_updated_at()
RETURNS trigger
LANGUAGE plpgsql
AS $$
BEGIN
  NEW.updated_at := now();
  RETURN NEW;
END;
$$;

DROP TRIGGER IF EXISTS trg_primitive_runs_updated_at ON public.primitive_runs;
CREATE TRIGGER trg_primitive_runs_updated_at
  BEFORE UPDATE ON public.primitive_runs
  FOR EACH ROW EXECUTE FUNCTION public.touch_primitive_updated_at();

DROP TRIGGER IF EXISTS trg_provider_tasks_updated_at ON public.provider_tasks;
CREATE TRIGGER trg_provider_tasks_updated_at
  BEFORE UPDATE ON public.provider_tasks
  FOR EACH ROW EXECUTE FUNCTION public.touch_primitive_updated_at();

Rollback (if ever needed)

DROP TABLE IF EXISTS public.provider_tasks;
DROP TABLE IF EXISTS public.primitive_events;
DROP TABLE IF EXISTS public.primitive_artifacts;
DROP TABLE IF EXISTS public.primitive_runs;
DROP FUNCTION IF EXISTS public.touch_primitive_updated_at();

Key design choices flagged by the previous engineer:
  • Fresh tables — not reusing generation_jobs. That table's reliability problems were the "biggest trap."
  • Storing credits in numeric(10,4) USD, not "credit units" — keeps the math honest and lets us reconcile against provider invoices directly.
  • Idempotency is a partial unique index (WHERE idempotency_key IS NOT NULL) so nullable keys don't collide.
  • RLS enabled but empty — defaults to deny-all from anon/authenticated. Service role only for now.
