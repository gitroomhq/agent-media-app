Once those gaps close, here's the end-user UX

A — REST API (logged-in agent-media user)

The user authenticates via the existing agent-media login flow (Supabase JWT). They get a Bearer token. They call:

GET https://api.agent-media.ai/v1/skills
→ returns the list of skills with their JSON-schema'd inputs.

POST https://api.agent-media.ai/v1/skills/make_portrait/run
Headers:
  Authorization: Bearer <agent-media token>
  Content-Type: application/json
  Idempotency-Key: my-portrait-1
Body:
  { "description": "...", "realism_target": "natural" }
→ 202 { run_id, workflow_id, skill, primitive, status: "submitted" }

POST https://api.agent-media.ai/v1/skills/make_character_sheet/run
Body (either):
  { "portrait_url": "https://pub-...r2.dev/vnext/..." }
or:
  { "portrait_image_base64": "iVBORw0KGgoAAAANSUhE..." }
→ 202 { run_id, workflow_id, status: "submitted" }

Status polling: GET /v1/videos/<run_id> already exists for the legacy path; a vNext equivalent GET /v1/primitives/runs/:run_id needs to be added (small follow-up).

B — MCP (Claude.ai integration, Cursor, custom agents)

Already partially wired: POST /mcp on api-v2 supports streamable HTTP. We just need to extend the tool list with two new MCP tools:

tools:
  - name: make_portrait
    description: "Generate one photoreal portrait."
    inputSchema: (from PortraitGpt2ToolInputSchema)
  - name: make_character_sheet
    description: "Generate a magazine-style character sheet from a portrait."
    inputSchema: (from MakeCharacterSheetSkillInputSchema)

Each tool, when called, calls the same skill registry under the hood — single source of truth. Same auth (the user's agent-media OAuth/JWT through MCP). End-user UX:

1. User connects "agent-media" as an MCP server inside Claude.ai (or Cursor).
2. User says "Make me a portrait of a friendly 28yo skincare creator."
3. Claude picks the make_portrait tool, fills inputs, calls api-v2 /mcp.
4. api-v2 routes through the skill registry → Temporal workflow.
5. Claude shows the R2 URL when the workflow finishes (Claude polls).

C — Skill Center UI (future)

Internal-only at first per the handover. Lists the same registry. "Run" button calls the same REST endpoints.

Authoritative source of truth

Every surface (REST, MCP, future UI) reads from one place:

services/api-v2/src/skills/registry.ts

Adding a new skill = add an entry there. REST and MCP pick it up automatically. No duplication.
