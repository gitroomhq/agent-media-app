Build plan — “photo + your voice → video of you, in your voice”

This is a port of proven code from media-worker-v2 into the vNext primitive runtime. Audio-first architecture (Approach B), as designed.

What already exists to port (legacy media-worker-v2)

Legacy fileGives us
elevenlabs-tts.js → cloneVoice()Voice cloning — POST /voices/add (Instant Voice Cloning) → returns voice_id
elevenlabs-tts.js → generateElevenLabsTTS()TTS in the cloned voice, tone presets, prosody continuity
talking-head.js (kling provider)Audio-driven lip-sync: image2video → lip-sync (mouth follows the TTS audio)
evolink-client.jsKling models via EvoLink (~55% cheaper) — we already use this key for Seedance
Net: no new R&D. We re-implement these as two TypeScript primitives in the vNext worker.

The build — 2 primitives + 1 composed extension

1. clone_voice new

in:  { voice_sample_url (R2), consent: true, name? }
do:  port cloneVoice() → ElevenLabs POST /voices/add
out: { voice_id }  → persist in new `voices` table (user_id, voice_id, name, created_at)

2. voiced_selfie new

in:  { character_sheet_url, script, voice_id, duration }
do:  1. ElevenLabs TTS(script, voice_id)         → audio.mp3 → R2
     2. Kling lip-sync(character image + audio)  → talking.mp4   (mouth follows real voice)
        └ auto-split >10s into ≤10s segments + stitch (Kling lip-sync degrades past ~10s)
out: { video_url }

3. extend make_ugc_video composed

photo + voice_sample + script
  → portrait/character_sheet   (identity, have it)
  → clone_voice → voice_id     (new)
  → voiced_selfie              (new; replaces the generic-voice selfie when a voice is supplied)
  → subtitles                  (have it)
  = video that looks AND sounds like the user

When no voice_sample/voice_id is supplied, it falls back to today's Seedance generic-voice selfie — fully backward compatible.

Wiring (same patterns, no new infra)

  • New clients: client/elevenlabs.ts, client/kling.ts (port).
  • New schema contracts → register in skill registry → auto-flows to REST + MCP + CLI + public plugin via existing codegen.
  • New migration: voices table. Credits: deduct at activity start (idempotent), refund on terminal failure — same as every primitive.
  • R2 + SSRF allowlist applies to voice_sample_url.

Deploy discipline (lesson from the incident)

  • No railway up. Deploy the worker via the GitHub path only (full checkout → builds dist/workflows correctly).
  • Confirm the new env secrets are present on the service before testing, and verify the worker boots clean (the "listening … queue=primitive-vnext-v1" log) after deploy.
  • Build incrementally: TTS client + clone_voice first (cheap to test) → then voiced_selfie lip-sync → then compose.
