Critical & High Findings (must fix before enabling in prod)

1. SSRF — reference_photo_url is fetched without origin allowlist

File: services/primitive-worker-vnext/src/activities/portrait-gpt2.ts:114

The Activity validates that the URL parses as a public HTTPS URL (the schema's isPublicHttpsUrl check), then fetches it. The schema validator uses DNS-time checks on the hostname — it does NOT survive DNS rebinding, and the content-type sniff happens after the request body is already received from the target. An attacker can supply https://attacker.com/img.png that 302-redirects to an internal IP, or use DNS rebinding to point a public hostname at a private IP between resolution and fetch.

Fix:

  • Restrict reference_photo_url to an allowlist of trusted origins — your R2 public URL prefix (https://pub-16e2ed8f6be84691845e91436920ce0a.r2.dev) and your Supabase storage public URL.
  • Reject all redirects (fetch(..., { redirect: 'error' })).
  • Disallow private/link-local IP ranges by resolving the hostname yourself and gating the request on the resolved address.

2. Artifact double-insert on retry → duplicate spend

File: services/primitive-worker-vnext/src/activities/portrait-gpt2.ts:161–181

If the Activity succeeds through the OpenAI call + R2 upload but fails at the primitive_artifacts INSERT (e.g. transient Supabase outage), Temporal retries the Activity. The retry sees the primitive_runs row in submitted state (not succeeded), redoes the OpenAI call (a second paid generation), overwrites the R2 object, and finally inserts a second artifact row. The user's account is debited twice.

Fix: at the top of the Activity, SELECT status FROM primitive_runs WHERE id = $1. If status is already succeeded, return the existing artifact + run from the DB instead of redoing the work. Alternatively add a unique constraint on primitive_artifacts (primitive_run_id, kind) and use upsert.

3. Heartbeat timeout is dead config — long OpenAI calls will be killed

File: services/primitive-worker-vnext/src/workflows/portrait-gpt2.ts:12 + activities/portrait-gpt2.ts

Workflow proxy declares heartbeatTimeout: '90 seconds' but the Activity never calls Context.current().heartbeat(). gpt-image-2 calls can routinely run 30–90s; if they exceed 90s without a heartbeat, Temporal kills the Activity and retries it (more spend).

Fix: either remove the heartbeatTimeout, or add heartbeat() calls before/after the OpenAI request and inside the R2 upload.

4. Idempotency partial unique is bypassed by UPSERT conflict-target choice

Files: supabase/migrations/20260527150000_vnext_primitive_runs.sql:46 + activities/portrait-gpt2.ts:95

Migration creates a partial unique on (user_id, primitive_id, idempotency_key) WHERE idempotency_key IS NOT NULL. Activity does UPSERT ... ON CONFLICT (id) DO UPDATE — but the conflict target is the PK, not the idempotency key. If the API re-submits with the same idempotency key but a freshly-minted UUID, the partial unique kicks in and rejects the INSERT with a hard error rather than returning the existing run. If the API re-submits with the same UUID, the UPSERT blindly overwrites status, input, etc.

Fix: in the API route, if an Idempotency-Key header is present, SELECT id FROM primitive_runs WHERE user_id=$1 AND primitive_id=$2 AND idempotency_key=$3 first. If a row exists, return it. Otherwise mint a fresh UUID and INSERT. The Activity UPSERT then keeps ON CONFLICT (id) only for the retry-same-UUID case.

5. Per-day budget cap race condition

File: activities/portrait-gpt2.ts:74–92

The day-cap query sums only succeeded rows (actual_credits_usd IS NOT NULL). Two concurrent submissions both read a clean slate before either has finished, both pass the check, both spend. Acceptable for low-traffic dev; not safe at scale.

Fix (for later): include submitted + running rows by their estimated_credits_usd in the sum, OR use a Postgres advisory lock per user_id for the check-and-reserve, OR a stored procedure that atomically checks-and-inserts.

Medium / Low Findings

6. Reference-URL 5xx classified as nonRetryable

portrait-gpt2.ts:117–121 — any non-2xx (including 500/503) raises nonRetryable. A transient storage blip permanently fails the run. Fix: only 4xx → non-retryable; 5xx / network errors → plain Error so Temporal retries.

7. OpenAI 4xx burns 3 retries

client/openai.ts re-throws everything as-is. A 400 content-policy rejection retries twice more (~$0.40 wasted per failed prompt at $0.20 each). Fix: catch OpenAI.APIError; for 400/401/451 throw ApplicationFailure.nonRetryable.

8. primitive_runs.id has no DEFAULT

Application supplies UUIDs today, which is fine — but a future code path that omits the id silently fails with a NULL error. Add DEFAULT gen_random_uuid() to be safe.

9. Budget query index miss

Add covering partial index:

CREATE INDEX idx_primitive_runs_budget_cap
  ON public.primitive_runs (user_id, created_at DESC)
  INCLUDE (actual_credits_usd)
  WHERE actual_credits_usd IS NOT NULL;

10. Singleton clients ignore key changes

client/openai.ts, client/r2.ts, client/db.ts all cache the first call's credentials. Fine for the long-lived worker process; will misbehave in any multi-config test. Optional cleanup.

11. numeric(10,4) tight

OK for image gens at ~$0.20. For per-token billing (e.g. Claude), 4 decimals loses precision. Widen to numeric(12,6) when convenient.

12. artifact.id as string cast

Supabase JS without generated types returns any. Cast is needed to satisfy TS but loses guarantees. Generate Database types and pass to createClient<Database>.
