Voice primitive — “upload a photo + your voice → video of you, in your voice”

Short answer: yes, very possible, and you already own most of the tech. Below is how it should be built and the one architectural decision that makes or breaks it.

Where we are today

  • make_simple_selfie calls Seedance with generate_audio: true → Seedance invents a generic synthetic voice and lip-syncs the face to it. The voice is not the user's.
  • The legacy media-worker-v2 already has working ElevenLabs code: elevenlabs-tts.js, dubbing.js (also Hume + OpenAI TTS). So TTS + voice handling is proven in this codebase — we port the approach into a vNext primitive, not invent it.

The one decision that matters: where does the voice come from?

You can't just generate a Seedance talking-head and swap its audio for the cloned voice — the lips were synced to Seedance's audio, so a swap drifts out of sync. There are two clean architectures:

ApproachFlowVerdict
A — Generate then dubSeedance makes video+voice → replace audio with ElevenLabs cloned voice → run a lip-sync re-alignment pass to re-match the mouth to the new audio.Works but 2 video passes, lip-sync risk, more cost/latency. This is essentially what legacy dubbing.js does.
B — Audio-first (recommended)ElevenLabs makes the cloned-voice audio first → feed that audio into an audio-driven lip-sync video model (lips follow the real audio). Audio is the source of truth.Cleaner, one source of truth, tightest sync. This is the right architecture.
Recommendation: Approach B. Voice is generated first and the mouth is driven from it, so lip-sync is correct by construction instead of patched after the fact.

Proposed primitives (2 new + 1 composed extension)

1. clone_voice new primitive

  • In: voice_sample_url (R2-hosted, ~30s–2min of the user talking) + consent: true.
  • Does: ElevenLabs Instant Voice Cloning (POST /v1/voices/add) → returns a voice_id.
  • Out: persisted voice_id (new voices table, or a column on the character/actor). One-time per person — reused across all their videos.
  • Note: ElevenLabs requires a consent/verification step for cloning a real voice. We must capture explicit consent in the UI/API and store it. Compliance, not optional.

2. voiced_selfie new primitive (or an optional voice_id on simple_selfie)

character_sheet_url + script + voice_id
   │
   ├─ 1. ElevenLabs TTS(script, voice_id)            → cloned-voice audio.mp3 → R2
   ├─ 2. audio-driven lip-sync video
   │        (character image + audio  →  mouth follows audio)   → talking.mp4
   └─ 3. (optional) subtitles primitive on top
  • Lip-sync engine: use the EvoLink Kling lip-sync you already use elsewhere (memory: it degrades past ~10s, so the primitive must auto-split scripts >10s into ≤10s segments and stitch — same rule we already enforce).
  • Extract audio before any re-encode to avoid A/V drift (existing house rule).

3. Compose: extend make_ugc_video composed

photo (upload)  ─►  portrait/character_sheet   (identity)   [have this]
voice sample    ─►  clone_voice → voice_id      (voice)      [new]
script + voice_id ─► voiced_selfie              (talking video) [new]
                   ─► subtitles                                  [have this]
                   = final video of the user, speaking in their own voice

End-user experience

  1. User uploads 1 photo + a short voice clip of themselves (and ticks consent).
  2. One call: make_ugc_video with portrait_image + voice_sample + script.
  3. Out: a 9:16 video that looks like them and sounds like them, lip-synced, optionally captioned.
  4. Their voice_id + character sheet are saved → every future video reuses them instantly (no re-upload).

How it fits the primitive runtime (no new patterns)

  • Same shape as existing primitives: Temporal workflow + activity, writes primitive_runs, uploads artifacts to R2, deducts credits at activity start (now idempotent), refunds on terminal failure.
  • New client: client/elevenlabs.ts (port from media-worker-v2/src/elevenlabs-tts.js). New env: ELEVENLABS_API_KEY.
  • New schema contracts: CloneVoiceToolInput, VoicedSelfieToolInput. Register in the skill registry → automatically flows to REST + MCP + CLI + public plugin via the codegen we already have.
  • Storage: voice samples + generated audio under vnext/primitive-runs/<id>/, R2-allowlisted (SSRF guard applies to voice_sample_url too).

Risks / things to decide

  • Lip-sync quality past 10s — must auto-split + stitch (proven constraint).
  • ElevenLabs consent/compliance — capture + store explicit consent for cloning a real voice; surface it in the UI.
  • Cost/latency — adds an ElevenLabs TTS call + a lip-sync video pass per clip; price the credit cost accordingly.
  • Quality bar — audio-driven lip-sync must hit the same realism bar as the selfie (no uncanny mouth). Validate the same way: render + eyeball.
  • IVC vs Professional cloning — Instant (fast, ~30s sample) is the right default; Professional (higher fidelity, more sample, hours to train) optional later.

Recommendation & sequencing

Build it as Approach B, two primitives (clone_voice, voiced_selfie) + extend make_ugc_video. Port ElevenLabs from the legacy worker rather than rebuild.

But not yet — finish validating the current 6-skill pass first (we're mid-Phase 2, the glow-fixed selfie is rendering now). Voice is a clean follow-on sprint once the base pipeline is signed off. I'd scope it as its own TaskML sprint.
