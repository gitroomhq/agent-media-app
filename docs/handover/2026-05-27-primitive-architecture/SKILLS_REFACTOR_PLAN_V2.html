Ecosystem reality check

There are TWO active skill ecosystems and they have different install commands. We need to support both:
EcosystemInstall commandLayout expectation
Anthropic Claude Code pluginsclaude /plugin install github.com/owner/repo.claude-plugin/plugin.json + skills/<name>/SKILL.md
claudemarketplaces.com (community)npx skills add <repo-url> --skill <slug>skills/<slug>/SKILL.md — they pick one skill at a time by directory name

Same on-disk layout satisfies both, which is convenient. Good news: skills/<slug>/SKILL.md is the universal shape.

Changes from v1 plan (architect review)

A GitHub Action on push to the private monorepo runs git subtree split --prefix=public-skill, force-pushes the result to gitroomhq/agent-media using a bot token. No human ever pushes to gitroomhq. Removes the leak-risk that triggered the prior memory rule.

9 (missing) Deprecation policy: slug is append-only. Breaking change = new slug (make_simple_selfie_v2). Old slug stays for 90 days with frontmatter x-deprecated: true.

What gets shipped

Phase A — In the private monorepo (yuvalsuede/agent-media)

  1. Codegen script at packages/schema/scripts/generate-skill-plugin.ts. Reads services/api-v2/src/skills/registry.ts + Zod schemas. Emits public-skill/.claude-plugin/plugin.json, public-skill/skills/<slug>/SKILL.md × 5, the composite agent-media-ugc/SKILL.md, and the shared reference/ tree (auth.md, pacing.md, realism-rubric.md).
  2. CI guard: pnpm gen:skills && git diff --exit-code public-skill/ blocks PR merges when registry changes aren't reflected.
  3. GitHub Action at .github/workflows/mirror-public-skill.yml that runs on push to main: git subtree split --prefix=public-skill -b _public_skill_HEAD && git push -f gitroomhq main. Bot token only.

Phase B — In the MCP server (@agentmedia/mcp-server)

  1. Bump to v0.6.0: surface the 5 vNext skills + the composite in tools/list.
  2. Add the device-flow OAuth first-run handler. Token cached at ~/.config/agent-media/credentials.json.
  3. Publish to npm. .mcp.json references npx -y @agentmedia/mcp-server@^0.6.

Phase C — Submission

  1. claudemarketplaces.com: submit github.com/gitroomhq/agent-media. Their install command becomes npx skills add github.com/gitroomhq/agent-media --skill make-ugc-video (etc., one per skill).
  2. Claude community marketplace at claude.ai/settings/plugins/submit: same repo. Their install command becomes claude /plugin install github.com/gitroomhq/agent-media.
  3. README badges + GitHub topics: claude-plugin, claude-skill, ugc-video, ai-video.

What I would NOT ship in this round

  • Postiz integration on gitroom — confirmed separate, partnership lands later.
  • Anthropic-official marketplace listing — they don't accept submissions yet.
  • Manual SKILL.md edits — all generated. No drift, no surprises.

Honest gaps in this plan

  • I have NOT verified the exact current frontmatter spec — Anthropic's plugin docs are evolving. The architect agent and the docs-lookup agent both flagged uncertainty here. I will dogfood-test by installing our plugin locally via claude /plugin install before submitting to any marketplace.
  • The device-flow OAuth in the MCP server is real work (~2-3 hrs). If you want to ship the skill repo this week, I can defer device flow and keep the README "agent-media login first" path as v1, then add device flow in v2.
  • The subtree mirror needs a bot account + a deploy key on the gitroomhq side. You'll need to provision that before the CI workflow can push.

Decision tree

Pick one path:
  1. Full v2 (everything above): ~1 day of work. Best architecture, deferred OAuth = manual agent-media login for first-run.
  2. Lean v2: skip the device-flow OAuth + the composite skill; ship the 5 primitives + codegen + CI mirror. ~3-4 hrs. Composite + OAuth land in a follow-up.
  3. Walking-skeleton: hand-write the 5 SKILL.md once (no codegen), copy by hand to gitroomhq, submit to claudemarketplaces.com today. Re-do properly next week. ~1 hr.

I recommend Lean v2. Buys us architecture + drift protection without burning a day on OAuth before we've seen install-side bugs.
